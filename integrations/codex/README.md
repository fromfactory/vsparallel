# Codex lifecycle integration

This optional integration adds coarse Codex activity to VSParallel. Install,
repair, or remove it from **Setup & diagnostics** in the desktop app. Production
users should not edit hook files by hand.

VSParallel recognizes these Codex events:

- `UserPromptSubmit` → `activity_detected`
- `Stop` → `turn_finished`
- `SessionEnd` → `session_ended`

Codex does not currently provide a matching event that lets this integration
reliably classify a failed or interrupted turn. If no terminal event arrives,
the saved activity eventually appears as **Unknown**.

Each local record contains five fields: schema version, SHA-256 session key,
working directory, coarse state, and timestamp. Prompt text, responses, source,
transcripts, tool data, and raw session IDs are discarded.

Codex requires user-level handlers to be reviewed and trusted. After setup, run
`/hooks` in Codex and review the three VSParallel handlers. VSParallel reads the
review state exposed by the installed Codex `app-server`, but never changes the
decision. Workspace settings can still disable a trusted handler.

Hook review and rate-limit queries depend on interfaces exposed by the installed
Codex version. VSParallel reports them as unavailable when that version does not
provide a compatible response.

Setup preserves unrelated handlers and keeps a private one-time backup of the
original hook file. Because it is a complete copy, the backup may include
unrelated secrets already present in that file. See [Privacy](../../PRIVACY.md)
for backup and deletion details.

[`hooks.example.json`](hooks.example.json) is a reference example of the
configuration generated by the app, not an installer.
